The pipeline, stage by stage

Six stages run in order. If one fails, the deployment stops there.

  1. 1

    GitHub 🔗

    A push to the main branch is the only trigger.

    Completed
  2. 2

    GitHub Actions ⚙

    A runner checks out the code and starts the workflow.

    Completed
  3. 3

    Maven 🔨

    Unit tests run, then the Spring Boot jar is packaged.

    Completed
  4. 4

    Docker 🐳

    The jar is copied into an image built from the Dockerfile.

    Completed
  5. 5

    Docker Hub 📦

    The image is pushed and tagged latest.

    Completed
  6. 6

    AWS EC2 ☁

    The instance pulls the image and restarts the container.

    Completed

How it works

          
From a commit on a laptop to a running container in Stockholm.

        


        
    
          
  1. A developer pushes code to GitHub.
    2. 
          
  2. GitHub Actions picks up the push and starts the workflow.
    3. 
          
  3. Maven runs the tests.
    4. 
          
  4. The Spring Boot application is packaged.
    5. 
          
  5. A Docker image is built from that package.
    6. 
          
  6. The image is pushed to Docker Hub.
    7. 
          
  7. The EC2 instance pulls the newest image.
    8. 
          
  8. The old container is replaced by a new one.
    9. 
        

      


      

        

          
About this project

        

        

          Automated Cloud Deployment is a cloud and DevOps project that shows continuous
          integration and continuous deployment end to end. The application itself is a
          small Spring Boot service; the interesting part is everything that happens
          between a commit and that service running on a cloud instance.
        

        

          This page is the project's front door: it reports what is deployed, how it got
          there, and which tools were involved. Figures marked as demo are placeholders
          until the workflow records real ones.
